1. Git, GitHub, GitFlic — что есть что?

Git

Git — система контроля версий. Она хранит историю изменений проекта локально.

git --version

# пример:
# git version 2.x.x
Git может работать без GitHub или GitFlic: локальный репозиторий сам по себе полноценен.

GitHub

GitHub — сервис для размещения Git-репозиториев и совместной работы. В VS Code базовые Git-операции доступны встроенно; для Pull Request и Issues используется расширение GitHub Pull Requests and Issues.

git remote add origin https://github.com/user/project.git
git push -u origin main

GitFlic

GitFlic — платформа для размещения Git-проектов. С локальным Git она работает через обычные remote URL, HTTPS или SSH.

git remote add origin https://gitflic.ru/project/user/project.git
git push -u origin master
Имя основной ветки зависит от настроек репозитория. В документации GitFlic по умолчанию для нового проекта указана master.

VS Code

VS Code использует установленный в системе Git и позволяет выполнять основные операции через панель Source Control и встроенный Terminal.

Ctrl + Shift + G
# открыть Source Control
Графический интерфейс VS Code и команды терминала работают с одним и тем же Git-репозиторием.

2. Первоначальная настройка Git

Проверить установку

git --version

Команду удобно выполнить в Terminal → New Terminal внутри VS Code.

Настроить имя

git config --global user.name "Ivan Petrov"

Настроить email

git config --global user.email "ivan@example.com"
Имя и email записываются в историю Git как данные автора коммитов. Это не данные для входа в аккаунт GitHub/GitFlic.

Проверить настройки

git config --global --list

3. Создание локального репозитория

Открыть папку в VS Code

File → Open Folder... → выбрать папку проекта.

# затем в Terminal:
git status

Инициализировать Git

git init

Создаётся скрытая папка .git, в которой Git хранит историю и служебные данные репозитория.

Через интерфейс VS Code

Откройте Source Control → Initialize Repository.

Ctrl + Shift + G
→ Initialize Repository
После инициализации проект является локальным репозиторием. Сам по себе git init ничего на GitHub/GitFlic не загружает.

Посмотреть состояние

git status

Показывает текущую ветку, изменённые, staged и неотслеживаемые файлы.

4. Изменение → Stage → Commit

Главная схема Git:

Файл
Changes
Stage
Staged
Commit
Local history
Push
# посмотреть изменения
git status

# добавить один файл
git add main.py

# добавить всё
git add .

# создать коммит
git commit -m "Добавлена главная программа"

# отправить на сервер
git push
Важно: сохранение файла, stage, commit и push — разные операции. Commit записывает изменения в локальную историю, а push отправляет локальные коммиты на remote.

Stage через VS Code

В Source Control у изменённого файла нажмите +.

Changes
  main.py       +

Staged Changes
  main.py

Commit через VS Code

Введите сообщение коммита в поле Source Control и нажмите Commit.

Add calculator

→ Commit

Хорошее сообщение

git commit -m "Добавлена проверка ввода"
Сообщение должно кратко объяснять, что изменилось.

Посмотреть историю

git log --oneline

5. Remote — связь с удалённым репозиторием

Посмотреть remote

git remote -v

Обычно основной remote называют origin.

Добавить remote

git remote add origin https://example.com/user/project.git

Изменить URL remote

git remote set-url origin https://example.com/user/project.git

Удалить remote

git remote remove origin

6. Работа с GitHub через VS Code

Вариант A — Publish to GitHub

Для локального репозитория VS Code может создать новый репозиторий GitHub и отправить туда локальные коммиты.

Ctrl + Shift + P

Git: Publish to GitHub
При публикации VS Code предлагает войти в GitHub, выбрать имя и public/private для нового репозитория.

Вариант B — клонировать GitHub

git clone https://github.com/user/project.git

cd project

В VS Code также можно выбрать Clone Repository.

Push в GitHub

git add .
git commit -m "Изменён интерфейс"
git push

Pull из GitHub

git pull

pull получает изменения с remote и интегрирует их в текущую локальную ветку.

Fetch — только получить информацию

git fetch origin
fetch загружает информацию о новых коммитах, не выполняя автоматически слияние с текущей веткой.

GitHub Pull Request

Для создания и просмотра Pull Request прямо в VS Code используется расширение GitHub Pull Requests and Issues.

Extensions
→ GitHub Pull Requests and Issues

7. Работа с GitFlic через VS Code

Клонирование GitFlic по HTTPS

git clone https://gitflic.ru/project/user/project.git

cd project

После клонирования откройте папку проекта в VS Code.

Подключение существующего проекта

cd my_project

git init

git remote add origin \
https://gitflic.ru/project/user/project.git

git add .
git commit -m "Initial commit"
git push -u origin master

Push в GitFlic

git add .
git commit -m "Добавлена новая функция"
git push -u origin master
Если upstream уже настроен, обычно достаточно git push.

GitFlic через SSH

ssh-keygen -t ed25519 -C "your_email@example.com"

# после добавления public key в GitFlic:
git remote set-url origin \
git@gitflic.ru:user/project.git

Проверить remote GitFlic

git remote -v

Убедитесь, что URL указывает на нужный проект.

GitFlic + VS Code

Для GitFlic можно использовать встроенную Git-поддержку VS Code: клонирование, stage, commit, branch, pull, push и remote выполняются обычными Git-операциями.

То есть VS Code не требует отдельного Git-клиента только для работы с GitFlic: важен установленный Git и корректно настроенный remote.

8. Ветки (branches)

Посмотреть ветки

git branch

Создать ветку

git branch feature-login

Создать и сразу перейти

git switch -c feature-login
В VS Code ветку также можно создать через имя текущей ветки в Status Bar.

Переключиться

git switch main

Удалить ветку

git branch -d feature-login

Отправить новую ветку

git push -u origin feature-login

9. Merge — объединение веток

# перейти в ветку, куда вливаем изменения
git switch main

# обновить её
git pull

# объединить feature-login
git merge feature-login
После успешного merge проверьте проект и при необходимости создайте отдельный коммит.

10. Конфликты слияния

Когда возникает конфликт?

Конфликт появляется, когда Git не может автоматически совместить изменения, например когда две ветки изменили один и тот же участок файла.

<<<<<<< HEAD
print("Версия A")
=======
print("Версия B")
>>>>>>> feature

Решение в VS Code

VS Code показывает варианты вроде Accept Current Change, Accept Incoming Change или позволяет вручную объединить код.

# после исправления файла:
git add main.py
git commit -m "Resolve merge conflict"

Отмена merge

git merge --abort
Осторожно: перед отменой операции убедитесь, что вы понимаете, какие незакоммиченные изменения у вас есть.

3-way Merge Editor

В VS Code конфликтный файл можно открыть в встроенном 3-way Merge Editor и сравнить текущую, входящую и итоговую версии.

11. .gitignore

Зачем нужен?

.gitignore указывает файлы и папки, которые Git не должен добавлять в обычный набор изменений.

# Python
__pycache__/
*.pyc
.venv/

# VS Code
.vscode/

# секреты
.env

Добавить .gitignore

git add .gitignore
git commit -m "Добавлен gitignore"

Важно

.gitignore не перестаёт отслеживать файл, который уже был добавлен в Git ранее.

git rm --cached .env
git commit -m "Перестал отслеживать .env"
Никогда не публикуйте пароли, токены, приватные SSH-ключи и другие секреты.

12. Отмена и восстановление изменений

Убрать файл из Stage

git restore --staged main.py

Изменения в файле сохраняются, снимается только staging.

Отменить незакоммиченные изменения

git restore main.py
Команда удаляет незакоммиченные изменения этого файла. Используйте её осознанно.

Посмотреть изменения

git diff

Посмотреть staged diff

git diff --staged

Stash — временно убрать работу

git stash

# вернуть позже
git stash pop
Удобно, когда нужно временно переключиться на другую ветку, не создавая незавершённый commit.

Просмотреть коммиты

git log --oneline --graph --decorate --all

16. Быстрый старт: новый проект → GitHub

# 1. Открыть папку в VS Code

# 2. В Terminal:
git init

# 3. Настроить Git (если ещё не настроен)
git config --global user.name "Ivan Petrov"
git config --global user.email "ivan@example.com"

# 4. Добавить файлы
git add .

# 5. Первый commit
git commit -m "Initial commit"

# 6. В VS Code:
# Ctrl + Shift + P
# Git: Publish to GitHub

# или вручную:
git remote add origin https://github.com/user/project.git
git push -u origin main

17. Быстрый старт: новый проект → GitFlic

# 1. Открыть папку проекта в VS Code

git init

git add .

git commit -m "Initial commit"

# 2. Создать проект на GitFlic

# 3. Подключить remote
git remote add origin \
https://gitflic.ru/project/user/project.git

# 4. Отправить основную ветку
git push -u origin master
Если в вашем GitFlic-проекте основная ветка называется main, используйте main вместо master.

19. Главное правило

ИЗМЕНИЛ
   ↓
ПРОВЕРИЛ DIFF
   ↓
git add
   ↓
COMMIT
   ↓
PUSH
   ↓
REMOTE (GitHub / GitFlic)
Не воспринимайте Save → Commit → Push как одну операцию. Сохранение изменяет файл, commit сохраняет снимок в локальной истории, а push отправляет commits на удалённый сервер.
