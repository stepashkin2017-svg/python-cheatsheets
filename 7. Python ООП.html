Основы

Класс — чертёж, объект (экземпляр) — конкретная вещь по этому чертежу. Объект хранит данные (атрибуты) и умеет действовать (методы).

Три принципа

  • Инкапсуляция — данные и методы вместе, внутренности скрыты.
  • Наследование — новый класс берёт возможности существующего.
  • Полиморфизм — разные объекты отвечают на один и тот же вызов по-своему.

Простейший класс

class Cat:
    pass

c = Cat()          # создали объект
type(c)            # <class '__main__.Cat'>
isinstance(c, Cat) # True

Классы и объекты

__init__ и self

__init__ вызывается при создании объекта. self — сам объект, всегда первый параметр метода.

class Cat:
    def __init__(self, name, age=1):
        self.name = name     # атрибут объекта
        self.age = age

tom = Cat("Том", 3)
tom.name    # 'Том'
tom.age     # 3

Методы объекта

class Cat:
    def __init__(self, name):
        self.name = name
    def meow(self):
        return f"{self.name}: мяу!"

Cat("Том").meow()   # 'Том: мяу!'

Изменение атрибутов

tom.age = 4              # изменить
tom.color = "серый"      # добавить новый
del tom.color            # удалить
hasattr(tom, "age")      # True
getattr(tom, "age", 0)   # 4
setattr(tom, "age", 5)
vars(tom)                # {'name': 'Том', 'age': 5}

Атрибуты класса

Общие для всех объектов, лежат в классе. Удобны для счётчиков и констант.

class Cat:
    count = 0                 # общий
    def __init__(self, name):
        self.name = name
        Cat.count += 1

Cat("a"); Cat("b")
Cat.count    # 2

Ловушка: изменяемый атрибут класса

Список в теле класса делят все объекты. Изменяемые данные создавайте в __init__.

class Bad:
    items = []            # общий на всех!
class Good:
    def __init__(self):
        self.items = []   # свой у каждого

__slots__

Ограничивает набор атрибутов и экономит память.

class P:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x, self.y = x, y
p = P(1, 2)
p.z = 3    # AttributeError

Виды методов

Метод объекта

Получает self, работает с данными конкретного объекта.

def birthday(self):
    self.age += 1

@classmethod

Получает класс cls. Часто используется как альтернативный конструктор.

class Date:
    def __init__(self, d, m, y):
        self.d, self.m, self.y = d, m, y
    @classmethod
    def from_str(cls, s):
        d, m, y = map(int, s.split("."))
        return cls(d, m, y)

Date.from_str("02.10.2026").y   # 2026

@staticmethod

Не получает ни self, ни cls. Обычная функция, логически принадлежащая классу.

class Calc:
    @staticmethod
    def is_even(n):
        return n % 2 == 0

Calc.is_even(4)   # True

Инкапсуляция и свойства

Уровни доступа (соглашения)

В Python нет жёсткого private, только договорённости об именах.

self.name      # публичный
self._cache    # «защищённый»: не трогать снаружи
self.__secret  # «приватный»: имя искажается

Искажение имени

class A:
    def __init__(self):
        self.__x = 1
a = A()
a.__x            # AttributeError
a._A__x          # 1 (всё же доступно)

@property — геттер

Метод читается как атрибут, скобки не нужны. Подходит для вычисляемых значений.

class Circle:
    def __init__(self, r):
        self.r = r
    @property
    def area(self):
        return 3.14159 * self.r ** 2

Circle(2).area   # 12.56636

Сеттер и проверка значений

class Temp:
    def __init__(self, c):
        self.celsius = c         # вызовет сеттер
    @property
    def celsius(self):
        return self._c
    @celsius.setter
    def celsius(self, v):
        if v < -273.15:
            raise ValueError("ниже абсолютного нуля")
        self._c = v

t = Temp(20)
t.celsius = -300    # ValueError

Только чтение

Свойство без сеттера нельзя перезаписать.

class User:
    def __init__(self, id): self._id = id
    @property
    def id(self): return self._id
u = User(7)
u.id = 8    # AttributeError

Магические методы

Методы с двойными подчёркиваниями вызываются Python сам, когда вы используете операторы и встроенные функции.

__str__ и __repr__

__str__ — для людей (print), __repr__ — для разработчика (в консоли, отладке).

class P:
    def __init__(self, x, y): self.x, self.y = x, y
    def __str__(self):  return f"({self.x}, {self.y})"
    def __repr__(self): return f"P({self.x}, {self.y})"
print(P(1, 2))    # (1, 2)
[P(1, 2)]         # [P(1, 2)]

Арифметика

def __add__(self, o):
    return P(self.x + o.x, self.y + o.y)
def __mul__(self, k):
    return P(self.x * k, self.y * k)
print(P(1, 2) + P(3, 4))   # (4, 6)
print(P(1, 2) * 3)         # (3, 6)

Сравнение

def __eq__(self, o):  return (self.x, self.y) == (o.x, o.y)
def __lt__(self, o):  return self.x < o.x
P(1, 2) == P(1, 2)   # True
sorted([P(3, 0), P(1, 0)])   # по __lt__
# остальные: __ne__ __gt__ __le__ __ge__

Контейнеры

class Deck:
    def __init__(self): self.cards = [1, 2, 3]
    def __len__(self):          return len(self.cards)
    def __getitem__(self, i):   return self.cards[i]
    def __contains__(self, x):  return x in self.cards
d = Deck()
len(d), d[0], 2 in d   # (3, 1, True)
for c in d: ...        # перебор работает через __getitem__

__call__ и __bool__

class Mul:
    def __init__(self, k): self.k = k
    def __call__(self, x): return x * self.k
double = Mul(2)
double(5)    # 10 — объект вызывается как функция

# __bool__ определяет истинность объекта в if

Контекстный менеджер

class Timer:
    def __enter__(self):
        print("старт"); return self
    def __exit__(self, *exc):
        print("конец")
with Timer():
    print("работа")
# старт / работа / конец

Композиция и dataclass

Композиция: «имеет»

Один объект содержит другой. Часто гибче наследования, когда связь не «является», а «состоит из».

class Engine:
    def start(self): return "вррр"
class Car:
    def __init__(self):
        self.engine = Engine()    # имеет двигатель
    def start(self):
        return self.engine.start()
Car().start()   # 'вррр'

@dataclass

Автоматически создаёт __init__, __repr__ и __eq__ по аннотациям полей.

from dataclasses import dataclass, field

@dataclass
class Point:
    x: int
    y: int = 0
    tags: list = field(default_factory=list)

Point(1)             # Point(x=1, y=0, tags=[])
Point(1) == Point(1) # True

Параметры dataclass

@dataclass(frozen=True, order=True)
class V:
    n: int
# frozen — неизменяемый, order — сравнение < >
V(1) < V(2)    # True

Интроспекция

isinstance(p, Point)    # объект этого класса?
type(p).__name__        # 'Point'
dir(p)                  # все атрибуты и методы
p.__dict__              # атрибуты объекта
help(Point)

Наследование

Класс-потомок получает атрибуты и методы родителя и может добавить своё или переопределить унаследованное. Запись: class Потомок(Родитель).

Базовое наследование

class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Dog(Animal):
    pass

d = Dog("Рекс")
d.name      # 'Рекс' — унаследовано
d.speak()   # '...'

Переопределение методов

Метод потомка заменяет метод родителя с тем же именем. Так работает полиморфизм.

class Dog(Animal):
    def speak(self): return "Гав"
class Cat(Animal):
    def speak(self): return "Мяу"

for a in (Dog("A"), Cat("B"), Animal("C")):
    print(a.speak())   # Гав / Мяу / ...

Проверка отношений

isinstance(d, Dog)      # True
isinstance(d, Animal)   # True — потомок «является» родителем
issubclass(Dog, Animal) # True
Dog.__bases__           # (<class 'Animal'>,)

Абстрактный класс

Задаёт интерфейс: потомки обязаны реализовать помеченные методы.

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self): ...

class Sq(Shape):
    def __init__(self, a): self.a = a
    def area(self): return self.a ** 2

Shape()      # TypeError
Sq(3).area() # 9

Множественное наследование и MRO

Класс может иметь нескольких родителей. Порядок поиска метода — MRO (слева направо, родитель после потомков).

class A: pass
class B(A): pass
class C(A): pass
class D(B, C): pass
D.__mro__   # D, B, C, A, object

Миксины

Небольшой класс с одной возможностью, подмешиваемый к другим.

class JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__, ensure_ascii=False)
class User(JsonMixin):
    def __init__(self, n): self.n = n
User("Аня").to_json()   # '{"n": "Аня"}'

super(): вызов родителя

super() возвращает прокси-объект, через который вы обращаетесь к методам следующего класса в цепочке MRO — для одиночного наследования это родитель.

Зачем нужен super() и что он даёт

  • Не теряем инициализацию родителя. Если в потомке есть свой __init__, родительский автоматически не вызывается.
  • Не дублируем код. Расширяем метод родителя, а не копируем его целиком.
  • Не привязываемся к имени. Переименовали или заменили родителя — вызовы super() менять не надо.
  • Корректно работает с несколькими родителями. Каждый класс в цепочке вызывается один раз по порядку MRO.
  • Не нужно передавать self. В Python 3 достаточно super() без аргументов.

Проблема без super()

Потомок определил свой __init__ и «забыл» родительский — атрибуты родителя не появились.

class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, breed):
        self.breed = breed      # name не задан!

Dog("лабрадор").name   # AttributeError

Решение: super().__init__()

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)   # инициализация родителя
        self.breed = breed

d = Dog("Рекс", "лабрадор")
d.name, d.breed   # ('Рекс', 'лабрадор')

super() и Родитель.__init__(self)

Явный вызов тоже работает, но жёстко привязан к имени класса и ломается при множественном наследовании (родитель вызовется дважды или не вызовется).

Animal.__init__(self, name)   # работает, но хрупко
super().__init__(name)        # предпочтительно

super() в обычных методах

Расширяем поведение родителя: берём его результат и дополняем.

class Animal:
    def describe(self):
        return f"Животное {self.name}"
class Dog(Animal):
    def describe(self):
        base = super().describe()
        return f"{base}, порода {self.breed}"
d.describe()   # 'Животное Рекс, порода лабрадор'

Расширение __str__ и __eq__

class Animal:
    def __str__(self): return f"Animal({self.name})"
class Dog(Animal):
    def __str__(self):
        return super().__str__() + f" / {self.breed}"
print(d)   # Animal(Рекс) / лабрадор

super() в @classmethod

class Base:
    @classmethod
    def create(cls):
        return cls()
class Child(Base):
    @classmethod
    def create(cls):
        obj = super().create()   # cls сохранится как Child
        obj.ready = True
        return obj
type(Child.create())   # <class 'Child'>

Цепочка из трёх уровней

class A:
    def __init__(self): print("A"); 
class B(A):
    def __init__(self): super().__init__(); print("B")
class C(B):
    def __init__(self): super().__init__(); print("C")
C()    # A  B  C — от корня к потомку

super() и MRO: «следующий в цепочке», а не «родитель»

При множественном наследовании super() идёт по __mro__. Если все классы вызывают super(), каждый метод выполнится ровно один раз, даже у общего предка.

class A:
    def hi(self): print("A")
class B(A):
    def hi(self): print("B"); super().hi()
class C(A):
    def hi(self): print("C"); super().hi()
class D(B, C):
    def hi(self): print("D"); super().hi()

D().hi()        # D  B  C  A  (A вызван один раз)
D.__mro__       # D, B, C, A, object

Заметьте: super() внутри B вызвал C, хотя C не родитель B. Именно так порядок MRO гарантирует однократный вызов.

Миксины и **kwargs

В кооперативном наследовании каждый класс принимает лишние аргументы и передаёт их дальше.

class LogMixin:
    def __init__(self, **kw):
        print("лог")
        super().__init__(**kw)
class Base:
    def __init__(self, name): self.name = name
class Svc(LogMixin, Base):
    pass
Svc(name="x").name    # лог → 'x'

Типичные ошибки

  • Забыли super().__init__() — у объекта нет атрибутов родителя.
  • Вызвали super().__init__() после того, как обратились к атрибутам, которые он создаёт.
  • Передали родителю не те аргументы — TypeError.
  • Написали super(self) вместо super().
  • Использовали super() в обычной функции вне класса — RuntimeError.

Полная форма

Старая запись, которая встречается в коде для Python 2. Результат тот же.

super(Dog, self).__init__(name)   # то же, что super().__init__(name)
Совет: для связи «является» используйте наследование, для «имеет» — композицию, а при наследовании вызывайте super() всегда, когда переопределяете __init__.
